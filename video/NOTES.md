# Conformance notes

Both films were conformed to `video-system/` in `ako/mxcli-intro-video`
(branch `claude/hyperframes-product-intro-b38m4h`, read-only). The narration
text and every captured artefact are unchanged from the first cut; what changed
is type, palette, plane, grid, voice, and how captured output that no longer
fits the frame is cut.

## What the system decided, against what was here before

| | before | after |
|---|---|---|
| Type | 'Segoe UI' / 'Cascadia Mono', absent on a clean machine, silently falling back to DejaVu | self-hosted Recursive variable file, `MONO` 0/1 for proportional and fixed-width |
| Palette | 43 hex values, five accent hues | the system's seven tokens, one accent, one accent event per frame |
| Plane | white entity cards with drop shadows, 14px/999px/4px radii | flat: `--panel` insets, 1px `--line`, no radius, no shadow |
| Grid | ad-hoc padding | safe area x96-1824 / y152-880, chrome label y76, hairline y104 |
| Captions | burned-in bar across the bottom | none; the bottom 17% is clear |
| Voice | Piper en_GB-cori-high at -16.2 LUFS | Kokoro `bm_george` at -18.6 LUFS, TP -1.5 |
| Music | none | a -32 LUFS bed, dropped 16 dB under result frames |
| Close | none | the catalogue lockup |

## Substitutions, and where output was cut

Glyph safety is checked against the shipped file's cmap
(`fonts/cmap.json`, regenerated by `scripts/cmap.py`), not an inherited list.
`·`, `—`, `–` and `…` are present; `≠`, `→`, `✓`, `✗` are not.

- The plan frame of film 1 previously rendered `6 contracts &rarr; 2`. The
  arrow is absent from the subset and would have been tofu; it now reads
  `6 contracts -> 2`, which is also what `EXPLAIN` prints.
- Mono is at the 30px floor, so captured SQL and plans no longer fit whole.
  Every cut is marked in the frame - `-- 3 guards`, `-- 2 joins`,
  `... 201 more`, `9 of 23 plan lines` - and `check.js` fails the build on an
  ellipsis with no marker.

## Two deviations, deliberate and visible

Both follow from holding the writing fixed while adopting the type's frame
budget, and neither can be fixed without rewriting narration:

1. **Length.** Film 1 is ~340s against Type C's 240-330s.
2. **Voice density.** ~85% against the type's 70-75%.

The cause is the same in both: these films carry 13 and 11 frames for 288s and
199s of narration, where the type assumes 22-30 frames for ~300s. The per-frame
tails *are* the type's (1.5s command, 5.0s result - the 3.5s floor plus "more if
the output is a table", which every result frame here is). Reaching 70-75%
density at these tails would mean splitting frames, which means rewriting the
script. Padding the tails to hit the density number instead would make the film
slower without making it clearer, so the numbers are reported rather than met.

## The one thing kept against the reference implementation

The reference records a single take and fits both a start offset and a ~1.065
clock scale to cut it. This pipeline records one browser context per scene, so
there is no cumulative drift to model: each clip carries its own two anchors and
is mapped linearly onto its own narration. Measured this pass: pre-roll ~0.65s,
scale 1.03-1.13, every clip landing within 0.05s of its target.

The caption bar that used to carry the compositor's only moving element is gone.
Measured after removing it: a 6s still tail records at 0.986x wall clock on a
frozen page and 1.133x with the chrome hairline drawing across the frame. It
does not collapse either way, and the linear map handles both.


## Film 3, built on the system rather than conformed to it

`view-entities-101` is the first deck written against the type rather than
retro-fitted, and it lands inside Type C without a deviation to report:

| | film 1 | film 2 | film 3 |
|---|---|---|---|
| frames | 13 | 11 | 22 |
| length | 340s | 235s | 328s |
| voice density | ~85% | ~82% | 72% |

The type's band is 240-330s at 70-75% density over 22-30 frames, and the reason
films 1 and 2 miss it is visible in the first row: 13 frames carrying 288s of
narration is 22s a frame, where the type assumes about 10. Nothing was padded
to reach the number here; the narration was written to the frame budget and
then cut by about 40s after the first audio build measured 359s.

One thing the type's own numbers do not cover: a beginner film needs more
frames for the same material, because each frame carries less. 22 frames for
five minutes is the floor, not the ceiling.


## Photographed frames

Film 3 carries three frames that are screenshots of Studio Pro 11.14.0 Beta
rather than output captured from the running app: the OQL editor, the data
grid's datasource dialog, and a text filter sitting in a column. They exist
because the editor is the one thing this pipeline cannot photograph — mxcli
writes the model, but nobody can screenshot a dialog that was never opened.

Three rules keep them honest and keep them inside the system:

1. **Each names its version in the sub line.** The rest of the film is
   10.24.24.119653; these three say `Studio Pro 11.14.0 Beta`, because the
   editor they show is a newer one.
2. **Cropped, never upscaled.** Each is cut to the region that carries the
   point and shown at or below its own pixel size (`.shot`, max-height 452px),
   so nothing is interpolated. The originals are in `docs/shots/sp-*.png`.
3. **A hairline, no card.** One 1px `--line` border, flush left with the
   type — framed as evidence rather than dressed up.

One is a bright white rectangle in a dark film: the page editor's preview of an
Atlas page. It was cropped down to the header band to reduce the area, and left
as it is otherwise. The alternative was to not show the thing the frame is about.

That frame is now paired with the filter's own captured SQL rather than with a
published-resource call, because the filter it shows turned out to be writable
in MDL after all — the syntax was in a skill reference, not in `mxcli syntax`.
So the film follows one page from datasource to `ILIKE` without changing
subject, and the screenshot is there for what it is: the editor, mid-edit.
